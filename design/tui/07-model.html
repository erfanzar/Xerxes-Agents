Decisions

  • Both stages on screen at once. A provider page that replaces itself with a model page hides the thing you are comparing against — you pick a provider because of the models behind it. The rail narrows the right pane; it never navigates away from it.
  • The rail carries auth state, not just names. oauth / api key / local / not configured answers "why can't I pick that one" before you try. Unconfigured providers stay visible and dimmed rather than being filtered out, because their absence is itself a question.
  • Families are groups, and groups carry counts (CLAUDE 5 · 3). A flat alphabetical list of 27 model ids is a search problem; six labelled families is a reading problem.
  • Badges are facts or they are absent. Context window and $/M come from the provider catalog. fable-5 has no published output price, so it gets no price badge — not "—", not "n/a", not an estimate. An invented number here would be quoted back to you as if the tool knew it.
  • The exact model id is right-aligned on every row. The short name is for choosing; the id is what ends up in config and in bug reports, and you should never have to guess the mapping.
  • ⏎ is session-scoped, ⇧⏎ writes the default. Changing your mind for one turn is the common case and gets the plain key. esc restores the previous screen and says out loud what you stay on.
