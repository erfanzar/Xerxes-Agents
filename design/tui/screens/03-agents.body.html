Decisions

  • Grouped by what you must do, not by what the agent is. NEEDS INPUT → WORKING → READY TO REVIEW is a work queue read top-down. A status-ordered list (running, done, failed) would bury the two agents that are stalled waiting on you behind seven that need nothing.
  • Failed agents live in READY TO REVIEW. Failure is a result you have to read, so it belongs to the same action as success — the red ● tells you which kind it is. A separate FAILED group would be a status group wearing an action label.
  • Each group's caption carries its own count (NEEDS INPUT · 2) so the header's total is never the only number. Truncation is stated out loud (▾ 1 more working) rather than silently cutting the list.
  • Cards lead with different content per group, on purpose. Needs-input leads with the question, working leads with the current activity (violet — the machine talking about itself), review leads with the result sentence. The one thing you'd read first is the one thing on the line.
  • Budget is right-aligned on every card in the same elapsed · tokens shape, so the column reads as a column and an expensive agent is visible without opening it.
  • The inspector answers in the order the questions arrive: what is it doing now → what has it done → what did it change → what did it cost. Cost includes the parent's share, because a subagent that bills its parent invisibly is how fleets get expensive.
