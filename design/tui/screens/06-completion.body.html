Decisions

  • The menu floats over the transcript and anchors to the composer, growing upward. It never pushes the transcript or moves the input line — the character you are typing must not change position while a list re-filters underneath it.
  • Eight rows, hard cap, and the overflow says so. +1 more · type to narrow is an instruction, not an apology: the fix for too many matches is more characters, and the footer says which lever to pull.
  • Commands and skills are grouped because they are genuinely different registries — one is built into the binary, one is files on disk that you can add to. The right-hand column names the source (builtin, repo, triage) so "why is this in my list" is always answerable.
  • Fuzzy matches are shown, not just ranked. /triage-flakes matches on an interior substring and highlights it, so a row that looks unrelated explains itself in place.
  • esc dismisses the menu and keeps the draft. The completion list is a view over your text, not its owner — the destructive reading of Esc (clear the line) is never the first one. Second Esc clears the line, third leaves the composer.
  • ⇥ completes, ⏎ commits. Separating "put the text in" from "act on it" means an accidental Enter in a filtered list can't fire a command you were only browsing.
  • @ reuses the exact chrome with a different registry and mid-sentence anchoring: it completes the token under the cursor, and file rows carry the state that matters when picking one (modified, ± counts, recently read).
